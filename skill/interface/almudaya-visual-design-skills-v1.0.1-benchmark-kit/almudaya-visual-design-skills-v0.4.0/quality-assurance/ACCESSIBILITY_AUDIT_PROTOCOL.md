# Accessibility Audit Protocol

Use applicable platform standards and project requirements. This checklist is a review aid, not a certification.

## Semantic and assistive technology
- Correct names, roles, values, headings, landmarks, and reading order
- Meaningful labels and instructions
- Status messages and errors announced appropriately
- Images and non-text content have suitable alternatives
- Tables, charts, maps, and complex visualizations have accessible equivalents

## Keyboard and focus
- All essential actions are keyboard operable where the platform supports keyboard input
- Focus is visible, logical, and not obscured
- Dialogs and overlays manage focus and return focus appropriately
- No keyboard traps except intentional, documented interaction contexts

## Visual and motion
- Text and controls meet the applicable contrast requirements
- Information is not conveyed by color alone
- Text resizes/reflows without loss of function
- Motion can be reduced or disabled where appropriate
- No flashing or animation that creates avoidable harm

## Input and cognition
- Target sizes and spacing fit the platform and user context
- Errors explain how to recover
- Time limits can be extended or avoided when appropriate
- Instructions are clear and consistent
- Alternatives exist for modality-dependent actions

Record standard/version, test method, environment, exceptions, and evidence. A screenshot-only review cannot establish conformance.
