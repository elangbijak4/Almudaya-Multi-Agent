# AVDS Benchmark Protocol

## Objective
Measure whether AVDS produces more task-appropriate, visually differentiated, accessible, adaptive, and implementation-consistent interfaces than a baseline coding-agent workflow.

## Experimental controls
Keep the following identical between baseline and AVDS-assisted runs:
- coding agent and model/version
- task prompt and product requirements
- framework, dependencies, and starter repository
- available assets and data
- time/token budget where practical
- target viewports and test environment
- evaluator rubric

Record unavoidable differences. Do not compare outputs generated by different models as if AVDS were the only variable.

## Procedure
1. Freeze the benchmark prompt and starter repository.
2. Run baseline generation.
3. Reset to the same starting point.
4. Run AVDS-assisted generation using v1.0.0.
5. Capture source commit, agent/model, duration, token/cost estimate if available, and environment.
6. Build and run both outputs using the same procedure.
7. Capture screenshots and interaction evidence at all required viewports.
8. Evaluate critical tasks, visual quality, accessibility, platform fit, and consistency.
9. Have at least two reviewers score outputs independently where possible.
10. Resolve scoring differences and document rationale.
11. Publish a report including failures, limitations, and raw evidence references.

## Repetition
Run at least 3 independent generations per condition when resources permit. A single run is a pilot, not a robust comparative benchmark.

## Scoring
Use `scoring-rubric.md`. Report dimension scores separately; do not hide weak dimensions inside one average.

## Validity threats
- Agent/model randomness
- Prompt sensitivity
- Different implementation effort
- Reviewer subjectivity
- Unequal tool access
- Different runtime environments
- Benchmark overfitting

Mitigate by freezing prompts, recording environment, repeating runs, blind review, and publishing evidence.

## Minimum acceptance
A benchmark is considered interpretable only if both baseline and AVDS outputs are runnable or the failure is explicitly recorded, evaluation coverage is stated, and evidence is attached for every scored dimension.
