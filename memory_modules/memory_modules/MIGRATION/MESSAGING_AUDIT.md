## 1. Message Envelopes & Schemas (`src/messaging/schema.ts`)

### 1.1 Direct Message Envelope (`DirectMessageSchema`, `#L66-L90`)
Persisted inside `<sessionDir>/inbox/<recipientBotId>/messages.json` (`InboxStoreSchema`, `#L92-L99`):
- `message_id: string` — Generated by `generateMessageId()` (`msg_${Date.now()}_${3-byte-hex}`, `#L146-L149`).
- `session_id: string` — Owning session ID.
- `sender_bot_id: string` — Canonical `bot_id` of an active registered bot, or an explicit typed principal (`'HUMAN' | 'SYSTEM' | 'OPERATOR' | 'ADMIN' | 'CONSOLE'`).
- `recipient_bot_id: string` — Canonical `bot_id` resolved via `BotService.resolveBotId()`.
- `timestamp: string` — ISO-8601 creation timestamp.
- `message_type: DirectMessageType` — `'DIRECT' | 'REQUEST' | 'RESPONSE' | 'NOTIFICATION'` (default `'DIRECT'`).
- `content: string` — Redacted non-empty message body (`redactSecrets(input.content.trim())`).
- `status: MessageStatus` — Legacy/combined status (`'unread' | 'read' | 'acknowledged' | 'RECEIVED' | 'PROCESSING' | 'COMPLETED' | 'RETRY_PENDING' | 'DEAD_LETTER'`).
- `read_at?: string`, `acknowledged_at?: string` — ISO-8601 timestamps.
- `metadata: Record<string, unknown>` — Extensible dictionary (redacted via `redactRecursively()`). Currently used for:
  - `{ correlationId: message.message_id }` on autonomous replies (`src/bot/agent-loop.ts#L417`).
  - `{ source: 'console_repl' }` on synthetic operator REPL messages (`src/bot/console.ts#L431`).
- **Delivery State Machine Fields (`#L80-L89`):**
  - `delivery_state: InboxDeliveryState` (`'RECEIVED' | 'PROCESSING' | 'COMPLETED' | 'RETRY_PENDING' | 'DEAD_LETTER'`, default `'RECEIVED'`).
  - `attempt_count: number` (default `0`).
  - `max_attempts: number` (default `3`).
  - `fence_token: number` (monotonic per-message integer incremented on every claim, default `0`).
  - `lease_owner: string | null` (e.g., `${botId}:pid-${process.pid}`, default `null`).
  - `lease_expires_at: string | null` (ISO-8601 timestamp, default `30000` ms from claim).
  - `last_attempt_at: string | null`.
  - `last_error: string | null`.
  - `idempotency_key?: string` (optional publisher deduplication key).

### 1.2 Broadcast Event Envelope (`BroadcastEventSchema`, `#L18-L26`)
Persisted as append-only JSONL lines in `<sessionDir>/broadcast/events.jsonl`:
- `event_id: string` — Generated by `generateEventId()` (`evt_${Date.now()}_${3-byte-hex}`, `#L141-L144`).
- `session_id: string`.
- `sender_bot_id: string` — Authenticated via `MessagingService.authenticateSender()`.
- `timestamp: string` — ISO-8601 timestamp.
- `category: BroadcastCategory` — `'ACTIVITY' | 'OBSERVATION' | 'DECISION' | 'TASK' | 'ARTIFACT' | 'QUESTION' | 'STATUS' | 'ALERT'` (default `'ACTIVITY'`).
- `content: string` — Redacted non-empty text.
- `metadata: Record<string, unknown>` — Redacted dictionary. Currently used in `AutonomousAgentLoop`:
  - Tool invocation audit (`category: 'ACTIVITY'`, `{ tool, arguments, iteration }`, `src/bot/agent-loop.ts#L222-L231`).
  - Tool success audit (`category: 'ACTIVITY'`, `{ tool, success: true }`, `#L353-L361`).
  - Task completion decision (`category: 'DECISION'`, `{ replyToMessageId, iterations }`, `#L422-L432`).

## 2. Routing, Authentication & Publisher Idempotency (`src/messaging/service.ts`)

1. **Sender Authentication (`authenticateSender`, `#L35-L54`, `AUD-10`):**
   - Rejects empty sender strings.
   - Permits explicit system/human principals (`HUMAN`, `SYSTEM`, `OPERATOR`, `ADMIN`, `CONSOLE`).
   - Otherwise resolves the sender via `botService.getBot(sessionId, trimmed)` and enforces `bot.status === 'active'`. Unregistered or stopped/stale bots cannot spoof messages or broadcasts.
2. **Recipient Resolution (`sendDirectMessage`, `#L292`):**
   - Resolves `input.recipient` (either `bot_id` like `BOT001` or `display_name` like `app_001`) to canonical `recipientBotId` via `botService.resolveBotId(sessionId, input.recipient)` before acquiring the session lock.
3. **Publisher Idempotency (`#L298-L305`):**
   - Inside `withSessionLock`, if `input.idempotencyKey` is provided and an existing message in `inbox.messages` has `m.idempotency_key === input.idempotencyKey`, `sendDirectMessage` returns the existing `DirectMessage` without appending a duplicate.

## 3. Delivery State Machine, Leases & Fencing (`src/messaging/inbox-state.ts`, `src/messaging/delivery.ts`)

### 3.1 Legal State Transitions (`isValidStateTransition`, `src/messaging/inbox-state.ts#L13-L47`)
```text
RECEIVED ──────► PROCESSING ──────► COMPLETED (terminal)
   │                 │
   │                 ├────────────► RETRY_PENDING ──► PROCESSING / COMPLETED / DEAD_LETTER
   │                 │
   │                 └────────────► DEAD_LETTER ────► RETRY_PENDING (manual requeueDeadLetter only)
   └──────────────────────────────► COMPLETED (direct CLI ack)
```

### 3.2 Claiming, Leasing & Monotonic Fencing (`InboxDeliveryService`, `src/messaging/delivery.ts`)
- **`claimNextMessage(sessionId, botIdentifier, consumerId, leaseDurationMs = 30000, excludeMessageIds = [])` (`#L24-L89`):**
  - Runs inside `storage.withSessionLock(sessionId)`.
  - Finds the first message in `inbox.messages` (FIFO) not in `excludeMessageIds` whose `delivery_state` is `'RECEIVED'`, `'RETRY_PENDING'`, or `'PROCESSING'` with an expired lease (`isMessageLeaseExpired`).
  - If `candidate.attempt_count >= candidate.max_attempts`, transitions it to `'DEAD_LETTER'`, saves inbox, and returns `null`.
  - Otherwise transitions `delivery_state = 'PROCESSING'`, `status = 'read'`, increments `attempt_count += 1`, increments `fence_token += 1`, sets `lease_owner = consumerId`, and sets `lease_expires_at = now + leaseDurationMs`.
- **`completeMessage(sessionId, botIdentifier, messageId, consumerId?, fenceToken?, options?)` (`#L96-L169`):**
  - Idempotent if already `'COMPLETED'`.
  - Unless `options?.adminOverride === true`, strictly verifies (`AUD-08`, `REQ-04`):
    1. `consumerId` is non-empty and matches `target.lease_owner`.
    2. Lease is not expired (`!isMessageLeaseExpired(target)`).
    3. `fenceToken` matches `target.fence_token`.
  - Transitions to `delivery_state = 'COMPLETED'`, `status = 'acknowledged'`, clears `lease_owner` and `lease_expires_at`, and sets `acknowledged_at`.
- **`failMessage(sessionId, botIdentifier, messageId, error, consumerId?, fenceToken?, options?)` (`#L176-L243`):**
  - Enforces the exact same `consumerId`, lease expiry, and `fenceToken` checks (`AUD-08`).
  - Records `last_error = error`, clears lease fields, and transitions to `'DEAD_LETTER'` (if `attempt_count >= max_attempts`) or `'RETRY_PENDING'` (`status = 'unread'`, `read_at = undefined`).
- **`recoverExpiredLeases(sessionId, botIdentifier)` (`#L278-L310`):**
  - Scans `inbox.messages` for `'PROCESSING'` messages with expired leases and transitions them to `'RETRY_PENDING'` or `'DEAD_LETTER'`.

### 3.3 Broadcast Cursor Semantics (`src/messaging/service.ts#L85-L279`, `src/bot/runtime.ts#L156-L176`)
- `BotRuntime.pollCycle()` calls `readBroadcasts(sessionId, { botId: this.botId, autoAdvanceCursor: false })`.
- It invokes `await this.onBroadcastCallback(evt)` for each event sequentially, and **only after the callback resolves without throwing** does it call `messagingService.advanceBroadcastCursor(this.sessionId, this.botId, evt)` (`AUD-07`, `REQ-05`).
- In `readInbox()`, pagination `limit` is applied **before** marking messages as `'read'` so unreturned messages remain `'unread'` (`AUD-06`, `REQ-04`).

## 4. Inter-Agent Handoff & Memory Reference Capabilities Today

1. **Current Handoff Mechanism:**
   - Agents coordinate and hand off work using `SEND_MESSAGE_TOOL` (`src/tools/messaging-tools.ts`), `AutonomousAgentLoop` auto-replies (`src/bot/agent-loop.ts#L409-L436`), and shared `work_log.jsonl` inspection via `GET_WORK_LOG_TOOL` (`src/tools/work-log-log.ts`).
   - Replies attach `metadata: { correlationId: message.message_id }`, and completion broadcasts attach `metadata: { replyToMessageId: message.message_id, iterations }`.
2. **Current Memory References in Messages:**
   - Neither `DirectMessageSchema` nor `BroadcastEventSchema` currently has explicit top-level `knowledgeRefs`, `executionRefs`, or `handoff` fields, though both schemas include `metadata: z.record(z.string(), z.unknown()).optional().default({})` which accepts structured metadata without breaking schema validation!
3. **PKU Phase 5 Integration Path:**
   - `DirectMessage.metadata` and `BroadcastEvent.metadata` already support embedding `knowledgeRefs`, `executionRefs`, and `handoff` payloads today with zero breaking changes to `CURRENT_MESSAGING_SCHEMA_VERSION = '1.0.0'`.
   - Additionally, optional top-level fields (`knowledge_refs`, `execution_refs`, `handoff`) can be added to `DirectMessageSchema` and `BroadcastEventSchema` as `.optional()` fields while maintaining 100% backward compatibility with all existing stored `messages.json` and `events.jsonl` files.
   - **Critical Constraint (`PKU-006`, `PKU-007`):** PKU message event capture and knowledge extraction must occur **after** or alongside existing persistence without altering `claimNextMessage`, `completeMessage`, `failMessage`, `fence_token` validation, or post-callback `advanceBroadcastCursor` ordering.
