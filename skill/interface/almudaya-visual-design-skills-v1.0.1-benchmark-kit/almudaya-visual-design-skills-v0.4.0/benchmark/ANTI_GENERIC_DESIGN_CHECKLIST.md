# Anti-Generic Design Checklist

Use this checklist to evaluate whether an interface is meaningfully designed for its product rather than assembled from a generic SaaS template.

- [ ] Primary task determines the page structure.
- [ ] Navigation model is justified by information architecture.
- [ ] Sidebar/topbar/dashboard cards are used only when useful.
- [ ] Visual identity is distinguishable beyond a palette swap.
- [ ] Typography and density match the product's content and users.
- [ ] Components reflect domain-specific tasks and data.
- [ ] Empty, loading, error, and success states are designed.
- [ ] Mobile/compact layouts change structure when necessary.
- [ ] Platform conventions are respected.
- [ ] Decorative charts, gradients, glass effects, and cards do not displace task clarity.
- [ ] Visual hierarchy remains coherent across screens.
- [ ] The interface has no unexplained repeated patterns or ornamental elements.

A checklist pass is not a substitute for user testing or accessibility evaluation.
