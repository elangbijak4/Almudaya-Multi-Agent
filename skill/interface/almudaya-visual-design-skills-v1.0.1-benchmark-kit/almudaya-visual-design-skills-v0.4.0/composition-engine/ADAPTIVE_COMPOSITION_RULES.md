# Adaptive Composition Rules

## Principles
- Adapt structure, not only dimensions.
- Preserve task priority and semantic order.
- Move secondary controls into contextual surfaces only when discoverability remains adequate.
- Avoid hiding critical status, safety, or confirmation information.
- Respect platform-specific navigation and input conventions.

## Common transformations
- Wide desktop: parallel work surface and inspector may be appropriate.
- Narrow window: convert parallel regions into sequential or switchable regions.
- Phone: prioritize one task surface; use native navigation and sheets where appropriate.
- Tablet: use compact navigation with optional persistent detail when space permits.
- TV: reduce dense controls, increase focus targets, and support directional navigation.
- Wearable: expose glanceable status and a small number of high-value actions.
- Automotive: minimize visual demand and interaction complexity; prioritize safety.
- Industrial HMI: preserve operational visibility, clear alarm hierarchy, and deliberate control interaction.
- Spatial XR: compose around spatial task context and ergonomic reach, not flat-screen assumptions.
- Voice: expose clear conversational states, confirmations, and recovery paths.

## Breakpoint policy
Do not prescribe universal pixel breakpoints. Use platform conventions, content pressure, and component minimums to derive size classes. Document the trigger and resulting structural change.
