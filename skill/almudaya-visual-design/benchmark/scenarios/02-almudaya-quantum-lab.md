# Scenario 02 — Almudaya Quantum Lab

## Product context
A desktop research environment for constructing, configuring, running, and inspecting quantum computing experiments or simulations.

## Primary journeys
1. Create or open an experiment.
2. Construct or inspect a circuit/experiment graph.
3. Edit operation and runtime parameters.
4. Run, monitor, cancel, or recover an execution.
5. Inspect outputs and compare results.

## Required screens
- Project/experiment workspace
- Experiment canvas
- Parameter inspector
- Execution console/status
- Results analysis

## Platform targets
- Desktop first (Windows or cross-platform desktop)
- Compact desktop window
- Optional web companion view

## Design challenge
Avoid a generic admin dashboard. The primary surface is a technical workspace. Dense information is acceptable when hierarchy, grouping, focus, and discoverability remain clear.

## Acceptance criteria
- Experiment structure remains inspectable while parameters are edited.
- Execution state and errors are visible.
- Configuration is distinguishable from immutable result evidence.
- Keyboard navigation and a non-canvas alternative are documented.
- Compact windows preserve critical runtime status.
- Data visualization communicates units, scales, and context.

## Visual differentiation prompts
Compare Scientific Visualization, Digital Laboratory, and Data Intelligence profiles. Explain which visual language best supports scientific work without adding decorative noise.
