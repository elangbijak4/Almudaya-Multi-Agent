# Migration Risk Register (`Phase 0`)

**Target:** Technical, operational, security, and concurrency risks identified during the Phase 0 audit of Almudaya Multi-Agent v0.3.3, along with concrete engineering mitigations and verification gates.

---

## Risk Matrix

| Risk ID | Severity | Area | Risk Description | Root Cause in Existing Code | Mandatory Mitigation Strategy | Verification Gate |
|---|---|---|---|---|---|---|
| **RISK-01** | **CRITICAL** | Concurrency & Locking | **Session Lock Contention & `LockTimeoutError`:** Adding synchronous PKU writes inside `FilesystemSessionStorage.withSessionLock()` could push lock hold times past `DEFAULT_TIMEOUT_MS = 5000` ms (`src/core/lock.ts#L35`) when multiple bots heartbeat (every 2s) and poll (every 1s). | All session files share a single directory lock `<sessionDir>/.lock` (`src/blackboard/filesystem.ts#L218-L228`). | 1. Never hold `<sessionDir>/.lock` while performing heavy PKU indexing/graph traversal.<br>2. Perform PKU shadow/event capture asynchronously or via an append-only outbox outside the critical section of `.lock`. | Concurrency stress tests (`tests/messaging/concurrent-messaging.test.ts`, `tests/core/lock.test.ts`). |
| **RISK-02** | **CRITICAL** | Messaging Reliability | **Premature Broadcast Cursor or Inbox ACK on PKU Failure/Hook:** If a PKU hook alters error propagation inside `BotRuntime.pollCycle()` (`src/bot/runtime.ts#L151-L230`), a message might be marked `COMPLETED` before callback execution or a broadcast cursor might advance on callback failure. | `pollCycle()` relies on strict sequential try/catch around `onBroadcastCallback` -> `advanceBroadcastCursor` and `onMessageCallback` -> `completeMessage`/`failMessage`. | Wrap all PKU runtime hooks in isolated non-throwing boundaries (`PKU-004`, `PKU-006`, `PKU-007`) so PKU outages or hook errors never alter legacy callback/ACK/fencing control flow. | `PKU-004`, `PKU-006`, `PKU-007` + existing `broadcast-cursor-atomic.test.ts` and `inbox-state.test.ts`. |
| **RISK-03** | **HIGH** | Storage Volume & Churn | **Heartbeat Event Storm in PKU:** `BotRuntime` calls `BotService.touchHeartbeat()` every 2,000 ms (`src/bot/runtime.ts#L112-L119`), which rewrites `registry/bots.json`. Naive capture of every `saveBotRegistry()` call would flood PKU with thousands of useless `last_seen_at` events. | `touchHeartbeat()` calls `saveBotRegistry()` on the full `BotRegistry` object (`src/bot/service.ts#L211-L235`). | Enforce explicit Persistence Qualification Policy (`Spec §2.1, §6.3`): ignore `last_seen_at`-only mutations; capture only semantic lifecycle transitions (`registerBot`, `renameBot`, `updateStatus` state changes). | Event-capture unit tests verifying 0 PKU events emitted on `touchHeartbeat()`. |
| **RISK-04** | **HIGH** | Data Migration | **Strict JSONL Parsing Aborting Legacy Work-Log Export:** `FilesystemSessionStorage.readWorkLogs()` calls `readJsonlFile` with `strict: true` (`src/blackboard/filesystem.ts#L554-L556`), which throws `CorruptedDataError` on a single malformed line before writing quarantine diagnostics (`src/core/jsonl.ts#L67-L72`). | `parseJsonl()` throws immediately when `options.strict === true`, bypassing lines 106–122 of `readJsonlFile()`. | In the Phase 2 Read-Only Legacy Bridge, read JSONL files using `readJsonlFile(..., { strict: false })` and record any `corruptRecords` in the migration diagnostic/quarantine report without mutating the source file or aborting the export (`PKU-005`). | Migration quarantine tests with injected malformed JSONL lines. |
| **RISK-05** | **HIGH** | Security & Secrets | **Unredacted Secret Persistence in PKU or External Adapters:** Candidate memory payloads (e.g., raw tool outputs, environment variables, or operator instructions) could contain API keys, tokens, or dynamically registered secrets (`--api-key`). | While `FilesystemSessionStorage` redacts broadcasts, inboxes, and work logs, new PKU entrypoints (`IPKUStore.putKnowledge`, `appendEvent`) could receive unredacted objects if called directly. | Enforce mandatory recursive redaction (`redactRecursively` from `src/execution/environment.ts#L172`) at the `IPKUStore` / Gateway ingress boundary before any serialization, hashing, or adapter dispatch (`PKU-008`). | `PKU-008` secret-canary test modeled on `tests/security/secret-redaction-canary.test.ts`. |
| **RISK-06** | **HIGH** | Security & Prompt Injection | **Cross-Bot or Cross-Project Prompt Injection via KOE Retrieval:** If KOE retrieves knowledge objects authored by untrusted peer messages or external notes and injects them directly into the system prompt without boundary delimiters, an attacker could break out of prompt context (`AUD-15`). | `buildDynamicSystemPrompt()` currently wraps `recentWorkLogsMarkdown` in `<<<UNTRUSTED_WORK_LOG_START>>>` with `escapePromptDelimiters()` (`src/ai/prompts.ts#L107-L109`). | KOE context assembly (`IKnowledgeOptimizationEngine.assembleContext`) must wrap retrieved evidence in escaped `<<<UNTRUSTED_KNOWLEDGE_CONTEXT_START>>> ... <<<UNTRUSTED_KNOWLEDGE_CONTEXT_END>>>` delimiters using `escapePromptDelimiters()`. | Prompt-injection regression tests (`tests/security/prompt-injection.test.ts`). |
| **RISK-07** | **MEDIUM** | Access Control & Privacy | **Individual Memory Leakage Between Bots (`PKU-009`):** Without strict scope enforcement in `IPKUStore.queryKnowledge()` and KOE, Bot A could query `scope: 'agent'` memories belonging to Bot B. | Currently, all bots in a session share `IBlackboardStorage` with no per-bot read ACL on `getInbox(sessionId, otherBotId)`. | Enforce mandatory `MemoryPermissionContext` validation on every PKU read/query/traverse call: `scope === 'agent'` requires `permission.principalId === object.ownerId` or an explicit share/handoff relation (`PKU-009`). | `PKU-009` cross-bot access denial test. |
| **RISK-08** | **MEDIUM** | Lifecycle & Deletion Safety | **Accidental Deletion of Shared Graph Nodes or Target Source Files (`PKU-015`, `PKU-017`):** Pruning a PMU tree branch or purging a PMU could delete `KnowledgeObject` nodes still referenced by another PMU/branch, or attempt to delete files in `ProjectRootRecord.path`. | New lifecycle operations (`prune`, `soft_delete`, `purge`) introduced by PKU (`Spec §10.4, §10.5`). | 1. Separate tree-node membership from `KnowledgeObject` storage and `KnowledgeRelation` edges (`PKU-015`).<br>2. Block `purge` when incoming cross-project or active references exist (`PKU-017`).<br>3. Never perform filesystem deletion outside PKU's dedicated storage directory. | `PKU-015`, `PKU-016`, `PKU-017` lifecycle safety tests. |
| **RISK-09** | **MEDIUM** | Workspace Resolution | **`CapabilityPersistence` Workspace Root Split (`process.cwd()` vs `workspaceRoot`):** `CapabilityPersistence` defaults to `process.cwd()` when instantiated by `ExecutionController.getInstance()`, placing `capabilities/audit.jsonl` in `<cwd>/sessions/<sessionId>` even when `FilesystemSessionStorage` uses a custom `workspaceRoot`. | `src/capability/persistence.ts#L25` (`options.workspaceRoot ?? process.cwd()`). | Document this split in the Phase 2 legacy bridge so capability grants/audits are discovered from the configured `CapabilityPersistence` path without breaking existing ACG tests. | Legacy export parity tests (`Phase 2`). |
| **RISK-10** | **LOW** | Build & TypeScript | **Scaffold Path Placement vs `tsconfig.json`:** `tsconfig.json` compiles `src/**/*` (`rootDir: ./src`). Currently the extracted scaffold contracts sit in `memory_modules/src/memory_modules/`. | ZIP extraction into `memory_modules/` subfolder. | Keep `src/` untouched during Phase 0 (`git diff src/` clean). In Phase 1, place canonical contracts at `src/memory_modules/` and verify `npm run build` (`tsc`) and `npm test` pass 100%. | Phase 1 Gate build & test check. |
