# Change Control Log — Almudaya Multi-Agent v0.3.5

Dokumen ini mencatat rencana perubahan menyeluruh dari **v0.3.4** menuju **v0.3.5**.

| ID Perubahan | Kategori | Asal (`v0.3.4`) | Target (`v0.3.5`) | Alasan Perubahan |
|---|---|---|---|---|
| **CHG-351** | Startup & Role | Operator menjalankan `session create` & `bot join/run` manual | `almudaya up` langsung menghidupkan `MASTER` (`BOT000`) + konsol HITL pada `t = 0` | Menjadikan orkestrasi otonom sebagai perilaku *default*, bukan emergen. |
| **CHG-352** | Terminal Spawning | Setiap terminal bot harus dibuka manual oleh manusia | `SpawnManager` otomatis melahirkan bot anak: default `--spawn-mode windows`, opsi `--spawn-mode multiplexed` | Menyeimbangkan keterbacaan tiap bot CLI dengan kerapian layar saat jumlah bot banyak. |
| **CHG-353** | Anti Ping-Pong & Relay | `APP-BUG-04`: memblokir seluruh auto-reply setelah 1 kali balas | **`PrDE`**: izinkan ping-pong hingga batas `N` (default 10), deteksi *Circular Relay* via `PrTransfer` (`--pr-no-progress 5`), mediasi `MASTER`, batas 10x ke HITL | Mendukung diskusi multi-langkah yang sah sambil memutus jalan buntu langsung maupun melingkar. |
| **CHG-354** | Stuck Loop Handling | Loop berhenti diam-diam di `maxIterations = 10` | **`PrIterasi`**: `MASTER` ambil alih saat iterasi/timeout/kuota habis, *Single-Model Fallback*, & alihkan ke model AI berbeda maks 3x sebelum HITL | Mengatasi *reasoning blind spot*, habis kuota, maupun sistem bermodel tunggal secara otomatis. |
| **CHG-355** | Bot Creation Governance | Bot belum punya mekanisme otonom untuk melahirkan spesialis | **`PrBot`**: worker dapat mengusulkan bot via `request_spawn_bot`; persetujuan oleh `MASTER` (maks 10 bot sebelum HITL) | Memberi fleksibilitas tim sekaligus mencegah ledakan token & RAM. |
| **CHG-356** | Master Resilience | Satu provider tunggal untuk bot | **`PrMasterFailover`**: rantai model cadangan otomatis untuk `MASTER` dan bot Moderator delegasi | Menghilangkan *Single Point of Failure* pada pengawas utama. |
| **CHG-357** | Workflow Termination | Hanya berhenti saat bot lupa membalas | **Macro-Loop + `GoalLedger`**: `MASTER` memelihara *Acceptance Criteria* & Consistency/Improvement bots hingga `GOAL_ACHIEVED` | Menjamin kelengkapan Peta Pekerjaan programmer sebelum berhenti. |
| **CHG-358** | Deadlock & Silent Death | Pesan buntu atau `Tugas 0` prematur menghentikan loop tanpa pemeriksaan | **`PrMEend`**: wajib pesan lanjutan + `CC: MASTER`, inspeksi 2-lapis, migrasi pesan/spawn baru, & verifikasi `Tugas 0` | Menutup celah terhentinya Macro-Loop secara diam-diam. |
| **CHG-359** | Global Capacity Ceiling | Belum ada batas global yang mengikat `MASTER` atas spek laptop, token, & waktu | **`PrBotGlobal`**: mengikat semua bot termasuk `MASTER` berdasar spek laptop (`HardwareAdvisor`), token, waktu (`ms \| infinite`), & **Bot Recycling** saat handover | Mencegah hang/habis RAM laptop atau membuka jendela *zombie* berlebih. |
| **CHG-360** | Protocol Modularity | Logika batas tersebar di agent loop dan fungsi terpisah | **Kontrak `IProtocol` & `ProtocolRegistry`**: seluruh 10 protokol diimplementasikan sebagai kelas atomic mandiri (`src/protocol/protocols/*.ts`) | Memungkinkan evaluasi, pengujian unit terisolasi, & pemakaian ulang protokol secara atomic. |
| **CHG-361** | Workspace Hak & Arbitrase | Belum ada token hak dinamis antar-bot & antrean prioritas intervensi | **`PrModerator`**: penengah (dapat didelegasikan `MASTER`), menerbitkan `CapabilityToken` ber-`fenceEpoch` cegah *zombie overwrite*, & `MasterInterventionQueue` `P0..P5` | Mencegah *concurrent file write race* dan *bottleneck* di `MASTER`. |
| **CHG-362** | Task & Token Handover | Transfer tugas tidak membawa posisi kerja maupun hak eksplisit + rentan file rusak parsial | **`PrTransfer`**: wajib `LastWorkPositionLog`, *pre-task checkpoints* (`checkpoints/`), & pemindahan atomik `CapabilityToken` (`fenceEpoch + 1`) di setiap `send_message` tugas | Menjamin kelanjutan konteks/hak yang sah & pemulihan file bila model gagal parsial. |
| **CHG-363** | Objective Completion Gate | Penetapan selesai pada `Tugas 0` hanya mengandalkan pembacaan teks LLM | **`PrGate`**: pemeriksaan fisik deterministik atas status `GoalLedger` & keberadaan/ukuran `targetFiles[]` di disk | Menghilangkan halusinasi penyelesaian (*false DONE*). |
| **CHG-364** | Crash Recovery Re-Attach | Restart sesi berisiko membuat jendela bot ganda | **`PrReattach`**: rekonsiliasi OS PID & *heartbeat* di `bots.json` saat `almudaya up` | Menyambung kembali jendela anak hidup tanpa spawn ganda. |
