## 2. Discrepancies Found Between Supplied `AUDIT_BASELINE.md` and Actual Source Tree

1. **Undocumented Subsystem — Agent Capability Governance (`src/capability/*`) & Persistent Files (`capabilities/grants.jsonl`, `capabilities/audit.jsonl`):**
   - `AUDIT_BASELINE.md` (§3.2, lines 50–65) lists the per-session directory structure without `capabilities/grants.jsonl`, `capabilities/grants.corrupt.jsonl`, and `capabilities/audit.jsonl`.
   - In actual code (`src/capability/persistence.ts#L28-L47`), `CapabilityPersistence` stores capability grants and mandatory security audit events in `<workspaceRoot>/sessions/<sessionId>/capabilities/`.
2. **`CapabilityPersistence` Default Workspace Root Divergence (`process.cwd()` vs `resolveWorkspaceRoot()`):**
   - `FilesystemSessionStorage` receives `workspaceRoot` resolved by `resolveWorkspaceRoot()` (`src/core/config.ts#L46-L57`).
   - However, `ExecutionController.getInstance()` (`src/execution/controller.ts#L20-L27`) instantiates `new CapabilityService()` -> `new CapabilityPersistence()` which defaults to `process.cwd()` (`src/capability/persistence.ts#L24-L26`) when no `workspaceRoot` is passed.
   - Consequently, running tests or tools through `ExecutionController.getInstance()` writes `capabilities/audit.jsonl` into `<repoRoot>/sessions/<sessionId>/capabilities/` on disk (observed in live untracked `sessions/S_CODING_BENCHMARK`, `sessions/S_MULTI_ROOT_BENCHMARK`, and `sessions/S_SEC_PROMPT_INJECTION_TEST`).
3. **Quarantine Sidecar Files in Session Directory:**
   - `FilesystemSessionStorage.readBroadcasts()` (`src/blackboard/filesystem.ts#L343`) configures `broadcast/events.corrupt.jsonl`.
   - `FilesystemSessionStorage.readWorkLogs()` (`src/blackboard/filesystem.ts#L553`) configures `work_log.corrupt.jsonl` (with `strict: true`).
   - `CapabilityPersistence.getGrantsRaw()` (`src/capability/persistence.ts#L91`) configures `capabilities/grants.corrupt.jsonl`.
   - Lock recovery (`src/core/lock.ts#L79, L283`) uses transient `.lock_barrier` directory and `.lock.corrupt.<timestamp>` backup files.
4. **Scaffold Extraction Nesting in Working Tree:**
   - `PKU_Memory_Modules_Scaffold_v0.1.0.zip` was extracted into `memory_modules/`, producing `memory_modules/memory_modules/` and `memory_modules/src/memory_modules/`.
   - During Phase 0, documentation under `memory_modules/` has been aligned so `memory_modules/MIGRATION/` exists at the canonical path while `src/` remains 100% unmodified (`git diff src/` is empty). Moving `memory_modules/src/memory_modules/` into `src/memory_modules/` is deferred to Phase 1 upon gate approval.
5. **Test Execution in Native Windows Environment vs Container Note:**
   - `AUDIT_BASELINE.md` (§1.8 & §6) noted that Vitest could not run in the Linux audit container due to platform-specific `node_modules` bindings.
   - On this native Windows workstation (`win32 x64`, Node `v24.21.0`), both `npm run build` (`tsc`) and `npx vitest run` execute cleanly and pass **47 / 47 test files (379 / 379 tests)**.
